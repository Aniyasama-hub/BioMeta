## 定义解释

### 基因集是什么，GMT 又是什么

基因集就是一份“为什么把这些基因放在一起”的成员名单。理由可以是同一条通路、同一种细胞的标志、同一个转录因子的靶基因，或某篇研究中按明确规则整理的表达特征。研究问题决定成员怎么选，文件格式负责把名单交给分析工具。

GMT 全称 Gene Matrix Transposed，是一种保存基因集的纯文本格式。每行放一个集合，同一行的字段用 **Tab 制表符**分开。第一格是集合名称或稳定 ID，第二格是描述字段，从第三格开始每格放一个基因。一个文件可以装多个集合，各行长度可以不同。[GSEA 官方格式说明](https://docs.gsea-msigdb.org/GSEA/Data_Formats/)

例如你整理了一个名为 `CUSTOM_REVIEWED_SET_V1` 的集合，成员是 `GENE_A`、`GENE_B`、`GENE_C`，那么文件的一行就是“集合 ID → 描述 → A → B → C”。这里用占位基因名练习格式，换成你的真实成员后再分析。

## 分析原理

### 从“基因属于集合”到“能参与计算的成员”

GMT 记录成员关系。表达值、差异统计量和样本分组来自另外的输入。比如集合 P 收了 A、B、C、D，表达表里有 B、C、E，匹配后能参与 P 分析的成员就是 B、C，共 2 个。原文件里写了 4 个成员，实际计算用到的是匹配后的 2 个。

这会影响基因集大小过滤。假设最小集合大小设为 10，某集合原有 12 个成员，匹配后剩 8 个，就会被过滤。遇到这种情况，先检查物种、编号和检测范围，再决定这个集合是否适合本次分析。

### 成员怎么选，决定结果回答什么

假设你想研究一种细胞状态，可以先从独立文献收集有实验支持的成员，并写下纳入规则。若直接用本次对比最显著的 50 个基因定义集合，再在同一份数据中检验它是否集中于排序前端，定义与检验就共享了同一批信息。更合适的做法是用独立资料定义，或把数据划分为发现与验证部分。

一个成员促进过程、另一个成员抑制过程，它们可能都属于同一通路。GSEA 或 GSVA 汇总的是所选成员的表达模式，机制解读还要结合成员作用。若要构建“上调特征”和“下调特征”，可分别建成两个集合，在说明文件里写明方向和证据。

## 分析操作

### 第一步：先写一张基因集说明卡

在填成员前，先写清下面几项。以后分享或改版时，这张卡能告诉别人集合是怎么来的。

| 项目 | 填写示例 |
| --- | --- |
| 要回答的问题 | 观察某个预先定义的转录特征在各样本中的表现 |
| 物种 | Homo sapiens |
| 编号类型 | 官方 SYMBOL；整份文件统一使用同一种类型 |
| 成员纳入规则 | 来自指定文献、按指定实验标准纳入 |
| 集合 ID | `MY_STUDY_SIGNATURE_V1`，同一文件内唯一 |
| 来源与日期 | DOI、数据库版本、下载或整理日期 |
| 修改记录 | 新增、删除或替换了哪些成员，以及原因 |

集合 ID 尽量简洁稳定，例如英文、数字和下划线；编号、名称、来源另存详细说明。发布新版时更新版本标识，便于追溯结果。

### 第二步：先用长表整理证据

初次整理时，推荐一行记录一个“集合—基因”关系，方便筛选和查重。可以下载下面的 CSV 草表，在 Excel 里填写。

<a href="/biomethod-assets/examples/gene-set-members-template.csv" download>下载成员整理 CSV 草表</a> · <a href="/biomethod-assets/examples/custom-format-example.gmt" download>下载 GMT 格式示例</a>

| set_id | description | gene_id | species | evidence |
| --- | --- | --- | --- | --- |
| CUSTOM_REVIEWED_SET_V1 | na | GENE_A | Homo sapiens | 填 DOI 或注释来源 |
| CUSTOM_REVIEWED_SET_V1 | na | GENE_B | Homo sapiens | 填 DOI 或注释来源 |
| CUSTOM_SECOND_SET_V1 | na | GENE_C | Homo sapiens | 填 DOI 或注释来源 |

同一个基因出现在两个不同集合里很常见，可以保留。一个集合内部重复出现同一个基因时合并为一个成员；对应的多条来源可以记在证据栏。空白编号、前后空格和过时别名应先整理。在 Excel 中把基因编号列设为文本，避免符号被自动改成日期或数字。

### 第三步：统一物种与基因编号

先选好人或小鼠，再把成员统一成表达数据可以匹配的编号。人类 SYMBOL 常见 `TP53`，小鼠对应符号是 `Trp53`；跨物种转换要使用明确的同源映射。Entrez、Ensembl 与 SYMBOL 是不同编号体系，填写时注明具体类型。

对别名或一对多映射，保留“原编号 → 新编号 → 来源 → 处理决定”的记录。Ensembl 版本后缀也要结合表达表的实际约定处理。合并前先抽查几个已知成员，确认文件与表达表确实在使用同一套名称。

### 第四步：在 Excel 里排成 GMT 的样子

1. 新建一个工作表，每行放一个集合。
2. A 列放集合 ID，B 列放描述字段，C 列起每格一个成员。
3. 正式导出的工作表从第一行直接写集合记录，去掉列标题。
4. 全部集合排完后，保存为“文本（制表符分隔）”。再用文本编辑器按 UTF-8 保存，文件名改成 `.gmt`。
5. 打开文件核对：同一行的成员由 Tab 分开；下一个集合从下一行开始；文件后缀确实是 `.gmt`，没有多出 `.txt`。

下面用 `[Tab]` 显示字段边界，便于看清结构；下载的示例文件中使用真实制表符。

```text
CUSTOM_REVIEWED_SET_V1[Tab]na[Tab]GENE_A[Tab]GENE_B[Tab]GENE_C
CUSTOM_SECOND_SET_V1[Tab]na[Tab]GENE_B[Tab]GENE_D
```

也可以直接在文本编辑器里写：输入 ID，按一次 Tab，输入描述，再按 Tab 逐个输入成员。一个集合结束后按 Enter。若现有基因名单是一列，可在 Excel 里复制后“选择性粘贴 → 转置”，排成同一行，前面补上 ID 和描述。

### 第五步：描述字段怎样填写

按照 GSEA 约定，第二字段可以填来源 URL；填 `na` 时，GSEA 会按集合名称生成相应的 MSigDB 描述链接。自建集合可用能访问的资料链接，详细证据放在配套说明表中。当前工作站对 URL 描述使用集合 ID 作为显示名；若填普通文字，则可作为本地显示描述。描述字段需要占一格，避免后面的第一个成员被当作描述读走。[官方字段规则](https://docs.gsea-msigdb.org/GSEA/Data_Formats/)

例如 `MY_SET_V1[Tab]https://example.org/my-set[Tab]GENE_A...` 把来源与成员分开；URL 应换成真实可追溯地址。成员编号里避免空格、引号和额外分隔符，每格保持一个编号。

### 第六步：先做格式与匹配检查

逐行检查集合 ID 是否唯一、描述是否一致、是否至少有一个非空成员、同一集合是否去重。GMT 使用 Tab 分隔；把逗号分隔 CSV 直接改后缀，会让解析器看不到正确的字段。

接着与表达表匹配，记录原始成员数、匹配数和缺失成员。若原来 30 个成员只匹配 2 个，先排查编号与物种。可到 [GMT 逐行代码教程](/biomethod/articles/gmt-code) 学习用 R 从 CSV 转换，并生成匹配检查表。

### 第七步：导入工作站并读结果

在支持本地 GMT 的 GSEA、GSVA 或通路分析里选择本地文件，按真实成员编号选择 SYMBOL 或基因 ID。以界面匹配报告与有效集合大小为准，保存本次使用的 GMT、说明卡和成员证据表。

GSEA 还需要完整有方向排序；GSVA 还需要逐样本表达矩阵；ORA 则需要候选与受检背景。原始 Count、VST、差异统计量各有用途，按所选分析的输入约定准备。

### 怎样维护自己的基因集

建议把 `my_sets_v1.gmt`、`members_v1.csv` 和一份说明放在同一目录。说明中写物种、编号、来源、成员规则和版本。更新时比较新增与删除的成员，保留 Git 记录；论文里交代使用的确切版本。

## 适用范围

适合把文献、数据库或研究设计中预先定义的成员整理为可复用集合。小集合可能在匹配后难以满足大小阈值，过大的集合又可能含义宽泛，应结合问题与方法选择。涉及商业资源或转载集合时，按实际来源许可使用，并保留出处。
