## 定义解释

富集分析判断一组候选基因是否比背景更集中地涉及某些已注释功能。GO 和 KEGG 提供功能注释，ORA 则用这些成员关系进行统计比较。

GO 从三个角度描述基因产物：BP 是参与的生物过程，CC 是所在或发挥作用的细胞结构，MF 是分子层面的活动。一个基因可以关联多个条目，条目之间也有上下级关系。KEGG PATHWAY 以通路图组织代谢、信号传递等关系；阅读 GO 时关注功能及层级，阅读 KEGG 时还可以沿通路图查看分子关系。

工作站只适配人和小鼠。GO 使用本机 `GO.db` 的名称及相应 `org.Hs.eg.db` / `org.Mm.eg.db` 的 `GOALL`、`ONTOLOGYALL` 映射。KEGG 使用官网物种通路成员与名称表。下方“当前工作站的注释库信息”读取实际包版本、缓存时间和记录数量；其中获取日期表示本机拿到资料的时间，发行号单独记录。

## 分析原理

过度代表分析常采用超几何检验。设背景有 N 个基因，其中 K 个属于某通路，候选集有 n 个，观察到 k 个通路成员，则考察至少如此重叠的概率：

$$P(X\geq k)=\sum_{i=k}^{\min(K,n)}\frac{\binom{K}{i}\binom{N-K}{n-i}}{\binom{N}{n}}$$

随后进行多重检验校正。背景应反映有机会进入候选集的受检、可映射基因，不能不加判断地换成全基因组。

### 候选集与背景集

候选集来自明确规则，例如调整后 P 值较小并且变化幅度达到下限。涉及显著性筛选时，背景优先保留具有有效原始 P 值的受检基因；没有原始 P 值时使用所选显著性列。仅变化幅度模式按有效变化值确定范围，不要求未使用的 P 列。随后与注释成员相交。候选集另按筛选规则确定，不把调整后 P 值缺失直接等同于未受检。若先把 DEG 表裁成显著基因，再让它兼任背景，就会改变比较含义。工作站对 BP、CC、MF 分别形成背景、检验和 BH 校正；合并图把三类结果放在同一画布，沿用各自的校正结果。

例如背景有 1,000 个可受检基因，候选有 100 个。某通路在背景中占 10%，在候选中占 30%，就值得进一步检验；如果只拿这 100 个候选当背景，比较基准会完全改变。

### P value、Adjusted P value 与 FDR

原始 P value 对应单项检验。本工作站 ORA 使用 BH 调整，输出 `p.adjust`；界面的 Adjusted P value 与 FDR（BH）都指向这一列，用于同一套结果的排序与筛选。上传 DEG 则可能同时存在 `P.Value`、`adj.P.Val`、`FDR` 等实际列，用户可以明确选择读取哪一列。若数值已经取负对数，应先还原为 0–1 概率再作为显著性列使用。

举例说，10 条通路的原始 P 值从小到大排列后，BH 会结合检验总数和各自位置调整；原始 P 为 0.01 的条目，调整值可能高于 0.05。

通路之间共享成员，GO 父子条目也有依赖。例如两个通路都由同样的三个候选基因命中，解释时要说明共享成员。富集衡量的是成员比例，机制研究还要回看方向和具体作用。

## 分析操作

### 操作步骤

选完整 DEG → 明确方向和阈值 → 匹配 ID → 记录受检背景 → 过滤基因集大小 → 检验与校正 → 解释具体成员。工作站保存实际背景与候选基因，便于复核。

打开 GO 或 KEGG 后，上传完整 DEG，保留唯一编号，以及这次需要的显著性列或变化幅度列。在“基因编号与名称映射”中核对列和物种；查看 `input_gene_mapping.csv`、`public_gene_mapping.csv`，解决未映射、歧义或编号/名称冲突，再解释结果。

### 先筛选基因，再排列通路

“候选基因筛选”读取上传文件实际列。仅显著性模式不要求 logFC，仅变化幅度模式不要求 P 值，同时筛选模式应用两项条件；上调、下调仍需要带正负号的变化列。`ora_input_selection.json` 保存实际列、阈值和方向，`ora_tested_universe.csv` 与 `ora_selected_genes.csv` 保存真实背景和候选成员。

“富集结果保留指标”决定哪些通路保留，“通路排序指标”决定展示顺序，可使用原始 P value、Adjusted P value、FDR（BH）、Gene ratio 或成员数量，并设置升降序。ORA 结果按成员比例、数量和显著性解释；基因的变化幅度到成员表达表中查看。

### GO 合并图与单类图

公共 GO 可导出三类合并图、各类单图或二者。合并图始终显示 BP、CC、MF 三个分类面板，每类取前 N 项（新建页面默认每类 5 项，可调整）；某类没有符合阈值的结果时，保留分类面板并说明，不用其他类别补齐。单图按所选类别分别输出。图型可选柱形、气泡或两种都导出，柱形支持水平和竖直方向。

分类面板保留 BP、CC、MF 标题，通路名称中的冗余前缀则清理掉。目的通路用颜色辅助定位，BP、CC、MF 仍按原分类显示。

### 目的通路的两种输入方式

直接填写与上传名称表是同一名单的两种入口，只读取当前选中的方式。可填正式名称或稳定 ID，如 `GO:0006955`，每行一项。KEGG 正式名称的物种尾注不会阻止匹配；匹配时使用稳定编号或正式名称。

匹配条目默认标红，背景可选填充。颜色输入 `#` 加六位十六进制值，如 `#C62828`；背景填 `transparent` 表示无填充，右侧色卡实时预览。标记应用于本次实际选中出图的通路，统计结果与排名沿用原分析。匹配与是否出图记录在 `target_pathway_matches.csv`。

### KEGG 官网机制图

公共 KEGG 默认下载本次出图通路的官网 PNG，也可选择所有符合结果阈值的通路或关闭下载。图片位于 `kegg_maps`，文件名包含通路 ID；`kegg_map_downloads.csv` 记录官网链接、文件、哈希与失败原因。网络失败时保留富集表并明确记录下载失败。

这些官网参考机制图展示已整理的分子关系；本次差异结果在富集表与成员表中查看。只改颜色、字号或图例可以重绘；更改筛选列、统计阈值、注释库或通路排序，应重新运行分析准备。

### 怎样阅读结果

条形或气泡的位置、大小、颜色分别应结合轴与图例阅读。富集说明注释成员较集中。进一步解释通路作用时，结合命中成员的表达方向、共享关系和实验背景。

### 常见问题与排查

没有富集结果可能来自基因太少、ID 未匹配、库不合适或阈值严格。不要为了得到结果任意更换背景；公共库使用还要遵守各自的使用条款。
